# 비전공자를 위한 서비스 흐름 설명

이 문서는 개발자가 아닌 사람도 Meerkatgram 서버가 어떻게 동작하는지 이해할 수 있도록 쉽게 설명합니다.

## 1. 이 프로젝트는 무엇을 하나요?

Meerkatgram 백엔드는 앱이나 웹 화면 뒤에서 동작하는 서버입니다.

사용자가 화면에서 로그인 버튼을 누르거나, 게시글 목록을 보거나, 이미지를 올리면 프론트엔드가 백엔드 서버에 요청을 보냅니다. 백엔드는 그 요청을 받아서 데이터베이스를 확인하고, 필요한 처리를 한 뒤 결과를 다시 보내줍니다.

쉽게 말하면 다음 역할을 합니다.

- 사용자가 누구인지 확인합니다.
- 게시글 데이터를 데이터베이스에서 가져옵니다.
- 업로드한 이미지를 서버 폴더에 저장합니다.
- 처리 결과를 정해진 형식으로 돌려줍니다.

## 2. 사용자가 로그인할 때

사용자가 이메일과 비밀번호를 입력하고 로그인 버튼을 누르면 다음 일이 일어납니다.

```text
사용자
 -> 프론트엔드 화면
 -> 백엔드 로그인 API
 -> 데이터베이스에서 이메일 확인
 -> 비밀번호 확인
 -> 로그인 성공 시 토큰 발급
 -> 사용자 정보와 토큰을 화면에 전달
```

여기서 토큰은 일종의 출입증입니다. 서버는 사용자가 매번 비밀번호를 다시 입력하지 않아도 되도록 토큰을 발급합니다.

이 프로젝트에서는 토큰이 두 종류입니다.

| 토큰 | 역할 |
| --- | --- |
| Access Token | API를 사용할 때 보여주는 짧은 출입증 |
| Refresh Token | Access Token을 다시 발급받기 위한 긴 출입증 |

Refresh Token은 쿠키와 데이터베이스에 저장됩니다. 나중에 토큰을 다시 발급할 때 서버는 쿠키에 있는 토큰과 데이터베이스에 있는 토큰이 같은지 비교합니다.

## 3. 사용자가 게시글 목록을 볼 때

사용자가 게시글 목록 화면에 들어가면 프론트엔드는 서버에 게시글 목록을 요청합니다.

```text
사용자
 -> 게시글 목록 화면 접속
 -> GET /api/posts 요청
 -> 서버가 page, limit 확인
 -> 데이터베이스에서 게시글과 작성자 정보 조회
 -> 최신순으로 정렬
 -> 응답으로 게시글 목록 전달
```

`page`는 몇 번째 페이지인지, `limit`은 한 번에 몇 개를 가져올지 뜻합니다.

예를 들어 `page=2`, `limit=6`이면 첫 6개를 건너뛰고 다음 6개를 가져옵니다.

## 4. 사용자가 게시글 상세를 볼 때

사용자가 특정 게시글을 클릭하면 서버는 게시글 번호로 데이터를 찾습니다.

```text
사용자
 -> 게시글 클릭
 -> GET /api/posts/{id} 요청
 -> 서버가 해당 id의 게시글 조회
 -> 게시글 내용과 작성자 정보 반환
```

게시글이 없거나 삭제된 게시글이면 서버는 찾을 수 없다는 오류 응답을 보냅니다.

## 5. 사용자가 이미지를 업로드할 때

프로필 이미지나 게시글 이미지를 올리면 서버는 파일을 받아 저장합니다.

```text
사용자
 -> 이미지 선택
 -> 프론트엔드가 파일 업로드 요청
 -> 서버가 파일 확장자 확인
 -> 저장할 파일명 생성
 -> 서버 폴더에 파일 저장
 -> 접근 가능한 이미지 주소 반환
```

파일명은 날짜와 랜덤 값으로 만들어집니다. 같은 이름의 파일이 덮어써지는 일을 줄이기 위한 방식입니다.

서버는 저장 후 다음과 같은 주소를 돌려줍니다.

```text
http://localhost:8080/files/posts/20260710_랜덤값.jpg
```

프론트엔드는 이 주소를 게시글 이미지나 프로필 이미지로 보여줄 수 있습니다.

## 6. 오류가 발생하면 어떻게 되나요?

서버는 오류가 나도 같은 형식으로 응답하려고 합니다.

예를 들어 로그인 실패, 잘못된 입력값, 권한 없음, 파일 업로드 실패가 모두 정해진 코드로 내려갑니다.

```json
{
  "code": "E01",
  "message": "NOT_REGISTERED_ERROR",
  "data": null
}
```

이렇게 통일하면 프론트엔드는 `code`를 보고 어떤 안내 문구를 보여줄지 결정하기 쉽습니다.

## 7. 서버 안의 역할 분담을 회사 조직에 비유하면

서버 코드는 여러 역할로 나뉘어 있습니다.

| 코드 영역 | 비유 | 실제 역할 |
| --- | --- | --- |
| Controller | 접수 창구 | 외부 요청을 받음 |
| Service | 담당 직원 | 실제 업무 규칙 처리 |
| Repository | 자료실 담당자 | 데이터베이스에서 자료 조회/저장 |
| Entity | 서류 양식 | 데이터베이스 테이블과 연결 |
| Request DTO | 접수 신청서 | 사용자가 보낸 입력값 |
| Response DTO | 결과 통지서 | 사용자에게 돌려줄 결과 |
| Global | 회사 공통 규정 | 보안, 오류 처리, 응답 형식 |

예를 들어 로그인은 다음처럼 진행됩니다.

```text
접수 창구(AuthController)
 -> 담당 직원(AuthService)
 -> 자료실(AuthRepository)
 -> 사용자 서류(User)
 -> 결과 통지서(AuthRes)
```

## 8. 현재 완성된 부분과 아직 비어 있는 부분

현재 완성되어 있거나 동작 흐름이 확인되는 부분은 다음과 같습니다.

- 회원가입
- 로그인
- 토큰 재발급
- 로그아웃
- 게시글 목록 조회
- 게시글 상세 조회
- 이미지 파일 업로드

아직 기능이 거의 없는 부분도 있습니다.

- 사용자 조회 API
- 게시글 작성 API
- 게시글 삭제 API

게시글 작성/삭제 관련 코드는 일부 주석으로 남아 있어, 과거 구현이 있었거나 앞으로 다시 구현할 가능성이 있어 보입니다.

## 9. 한 줄 요약

Meerkatgram 백엔드는 사용자의 요청을 받아 인증을 확인하고, 데이터베이스와 파일 저장소를 사용해 필요한 정보를 처리한 뒤, 항상 일정한 응답 형식으로 결과를 돌려주는 서버입니다.
